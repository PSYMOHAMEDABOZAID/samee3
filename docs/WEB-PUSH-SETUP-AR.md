# تشغيل إشعارات الويب وإحصاء التثبيتات

## 1. حساب خدمة Firebase

افتح مشروع Firebase الحالي `samee3-fb475` ← إعدادات المشروع ← Service accounts ← Generate new private key. احتفظ بالملف خارج المستودع.

أضف في Vercel ← Settings ← Environment Variables للبيئة Production:

| المتغير | القيمة |
| --- | --- |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | محتوى ملف حساب الخدمة كاملًا كما هو |
| `FIREBASE_PROJECT_ID` | `samee3-fb475` |
| `SAMEE3_PUBLIC_ORIGIN` | `https://samee3.vercel.app` |

يمكن بدل JSON استخدام `FIREBASE_CLIENT_EMAIL` و`FIREBASE_PRIVATE_KEY`. لا تضعها في متغير يبدأ بـ `NEXT_PUBLIC_`. يحتفظ الكود بمفاتيح الخدمة في الخادم فقط.

يلزم Cloud Firestore مفعلًا وحساب خدمة يملك صلاحية العمل على قاعدة المشروع. أرقام التثبيتات والاشتراكات في مجموعات جديدة تخص الخادم، وقواعد المنع الافتراضية الموجودة أصلًا تمنع قراءتها من الزوار. مسار الإدارة يتحقق من رمز دخول Firebase ومن دور `admin` الفعلي وحالة الحساب.

## 2. مفاتيح إشعارات الويب

داخل نسخة المشروع على الكمبيوتر:

```bash
npm ci
npm run push:keys
```

أضف القيم الناتجة في Vercel:

| المتغير | الاستخدام |
| --- | --- |
| `NEXT_PUBLIC_WEB_PUSH_VAPID_KEY` | المفتاح العام الذي يحتاج المتصفح قراءته |
| `WEB_PUSH_VAPID_PRIVATE_KEY` | المفتاح الخاص؛ يبقى في الخادم |
| `WEB_PUSH_SUBJECT` | `mailto:` متبوعًا ببريد الإدارة الحقيقي |
| `CRON_SECRET` | السر العشوائي الناتج |

احتفظ بنفس زوج VAPID بعد التشغيل حتى تستمر الاشتراكات. لا تنشر مخرجات الأمر أو ملف حساب الخدمة في GitHub. أعد نشر Vercel بعد إضافة المتغيرات لأن المفتاح العام يدخل في بناء الواجهة.

## 3. تشغيل الساعة كل دقيقة

المجلد `workers/reminder-clock` يحتوي Cloudflare Worker بسيطًا يستدعي خدمة الإرسال في سميع. هذا مسار مستقل عن Vercel Cron؛ لم نضف جدولًا كل دقيقة في `vercel.json` لأن خطة Hobby لا تقبله.

في حساب Cloudflare الخاص بك، أنشئ/انشر Worker بهذه الملفات، أو من الكمبيوتر:

```bash
cd workers/reminder-clock
npx wrangler login
npx wrangler secret put CRON_SECRET
npx wrangler deploy
```

عند طلب قيمة `CRON_SECRET` أدخل **نفس** القيمة الموجودة في Vercel. ملف `wrangler.toml` يحتوي عنوان سميع وجدول `* * * * *`. إذا غيرت نطاق سميع غيّر `SAMEE3_ORIGIN` أيضًا.

يمكن استخدام أي مجدول موثوق يستدعي `POST https://samee3.vercel.app/api/cron/reminders` كل دقيقة برأس `Authorization: Bearer <CRON_SECRET>`؛ لا تستخدم رابطًا عامًا يحمل السر في الاستعلام، ولا تعتمد على GitHub Actions لتنبيه أذان بدقة الدقيقة.

## 4. الاختبار من جهازك

1. افتح الإدارة. ستظهر التثبيتات المرصودة واشتراكات الويب وآخر تشغيل للمجدول. «لم يعمل المجدول بعد» تعني أن الخطوة السابقة لم تكتمل.
2. على الآيفون: Safari ← مشاركة ← إضافة إلى الشاشة الرئيسية، ثم افتح الأيقونة. اضغط تفعيل الإشعارات، وافق من النظام، واضبط `/notifications`.
3. اضغط «اختبار إشعار». يرسل الخادم إشعارًا لهذا الاشتراك وحده. أعد الاختبار بعد نصف دقيقة عند الحاجة.
4. اختر تذكيرًا بعد دقائق، واحفظه، ثم أغلق التطبيق وتحقق من وصوله. راجع المنطقة الزمنية وموقع الصلاة وطريقة الحساب.
5. على الكمبيوتر وأندرويد استخدم متصفحًا يدعم Push؛ نسخة أندرويد الأصلية تحتفظ بمجدولها المحلي السابق.

## التشغيل والخصوصية وحدود الخدمة

- الإشعارات تحتاج إنترنت ودعم Push وموافقة المستخدم؛ أوضاع التركيز وقيود النظام قد تمنع ظهورها أو صوتها. الجدولة كل دقيقة ليست منبهًا مضمونًا بالثانية.
- التذكيرات تشمل القرآن والأذكار والحديث والاستماع والمكتبة يوم الجمعة والصلوات المختارة. لا تُرسل الصلوات الفائتة بعد عودة الخدمة كدفعة متأخرة.
- مصدر مواقيت الصلاة واحد في العرض والإرسال، مع الموقع والطريقة والمذهب والمنطقة الزمنية المحفوظة. حدّث الموقع عند السفر.
- يحتفظ الخادم باشتراك Push والمواعيد وإحداثيات الصلاة المقربة عند اختيارها. لا يجمع سجل جهات اتصال، ولا يحتاج تسجيل دخول للاشتراك.
- يمكن إيقاف الاشتراك من صفحة الإشعارات. تُزال اشتراكات Push التي يعلن المزود انتهاءها بـ404/410.
- العدد في الإدارة هو عدد نسخ مرصودة، وليس عدد أشخاص أو إثبات اكتمال تحميل APK. يعتمد على معرّف محلي عشوائي؛ مسح بيانات التطبيق أو تثبيت مستقل قد يُحسب نسخة جديدة.
- يُعالج المسار حتى 80 اشتراكًا مستحقًا في الجولة مع أقفال تمنع التوازي لنفس الاشتراك. عند توسع الاستخدام الكبير يلزم زيادة سعة الجدولة/تقسيم الدفعات ومراقبة حالة المجدول.
